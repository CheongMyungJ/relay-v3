# M2.1 평가 보고

2026-11-05. 숫자의 원본은 [primary.md](primary.md)(규약대로 낸 표)와 [result.md](result.md)(0단계와 판정)이고, 도중에 본 것은 [log.md](log.md)에 있다. 이 글은 그것을 쉬운 말로 다시 쓴 것이다.

## 한 줄 요약

**M2.1은 사람 손을 줄이면서 결과는 오히려 나아졌다.** 새 앱(M2.1)은 옛 빌드(M2에 버그 고침만 더한 것)보다 사람 차례가 회당 4번 적었고, 숨긴 시험도 더 많이 통과했다. M2에서 회당 11.5번 많던 v2 자율과의 차이는 이번 횟수로는 가를 수 없을 만큼 줄었다. 토큰도 40% 덜 썼다.

## 1. 무엇을 견줬나

| 이름 | 무엇 |
|---|---|
| **M2.1** (relay3-m21) | M2 평가의 마찰을 고친 새 빌드. V30은 0단계 결과대로 메모로 내렸다 |
| **M2 + 고침** (relay3-m2p) | M2 평가의 빌드에 평가 중 찾은 버그 셋만 고친 것. 같은 날 돌린 기준 |
| **v2 자율** (relay@auto) | 옛 앱의 자율 모드 |

- 결론은 **봉인한 일 셋**에서만 냈다. M2.1을 설계할 때 보지 않은 일이다: 모듈 셋 만들기(39), 원인이 둘인 요약 메일 중복(47, 이번에 새로 만듦), 증상과 원인이 다른 곳에 있는 재고 버그(09). 세 쪽을 5번씩, 45번 돌렸다.
- 설계에 쓴 일 넷(07, 14, 19, 40)은 M2.1만 5번씩 20번 돌려, 고친 것이 실제로 일하는지 보는 데만 썼다.
- 사람 역할은 M2처럼 AI가 맡았다. 결과가 맞았는지는 숨긴 시험으로 본다.
- 실제 실행 65번, 오프라인 리뷰 재생 54번이다. 도구 문제는 0번이었다. 컨테이너가 한 번 다시 켜져 배치 1의 47을 처음부터 다시 돌렸다.

## 2. 결과 (봉인한 일 셋의 평균)

| | M2.1 | M2 + 고침 | v2 자율 |
|---|---|---|---|
| 숨긴 시험 통과 | **15/15** | 12/15 | 13/15 |
| 사람 차례 | **12.9** | 17.0 | 13.9 |
| 걸린 시간(분) | 3.1 | 4.4 | 3.9 |
| 토큰(천) | **731** | 1,228 | 862 |
| 시험 점수(1~5) | 3.8 | 4.1 | 4.2 |

- **결과의 질:** M2.1이 낮지 않았다. 오히려 높았다(+20%포인트, 우연이 아님). 차이는 원인이 둘인 47에서 났다. M2.1은 5번 모두 두 원인을 다 고쳤고, M2 + 고침은 2번, v2 자율은 3번이었다.
- **사람 손:** 회당 4.1번 줄었다(우연이 아님). 정해 둔 기준('2번 넘게 줄었음')을 넘었다.
- **v2 자율과의 차이:** M2.1이 1.1번 적었지만 이번 횟수로는 가를 수 없다. M2에서는 v3가 11.5번 많았다.
- **시험 점수**는 M2.1이 조금 낮다(−0.3). 리뷰가 '경계값 시험이 없다'는 가벼운 지적을 메모로 돌리게 바꾼 것(V26)의 값으로 본다.

## 6. 아직 남은 마찰 (다음 고칠 거리)

1. **지킴 시험이 새 함수를 불러 기준에서 돌지 못한다.** 그래서 지킴 줄이 '증거 없음'으로 남는다(39, 19, 40에서 되풀이). V28이 이를 막으려 했지만, 시험이 승인 뒤에 써져 돌 기회가 없었다.
2. **계약 예시가 글로 적혀 시험이 값으로 읽지 못한다.** 그래서 리뷰가 '예시와 시험 불일치'를 거듭 올리고, 상자가 뜨고, 사람이 [그래도 끝내기]로 넘긴다(47, 09, 14, 07).
3. **[세션에 넘기기]를 누르면 걸어 둔 끝이 풀린다.** 세션이 고친 뒤 사람이 [끝내기]를 다시 누르고 리뷰를 다시 기다린다.
4. **미리 리뷰가 [끝내기]에 맞춰 준비되지 않는다**(V23의 20초).
5. **걸어 둔 끝이 메모만 있으면 조용히 끝난다.** 사람이 지적을 못 보고 지나간 일이 있었다.

## 8. 읽을 때 조심할 것

- **사람 역할이 AI다.** 특히 [끝내기]를 매우 빨리 누른다. 그래서 미리 리뷰와 되먹임(V23, V24)의 효과는 실제 사람보다 작게 잡혔을 수 있다.
- **봉인한 일 셋, 쪽마다 5번이다.** 결과의 질 차이는 원인이 둘인 47 하나에서 났다. 다른 두 일에서는 모두가 다 맞혔다.
- **봉인한 47은 이번에 새로 만들었다.** 설계자는 배치가 끝날 때까지 숨긴 시험과 참조 패치를 열지 않았고, 열기 전에 sha256이 고정 때와 같은지 확인했다.
- **V30은 계획과 달리 메모로 돌았다.** 0단계에서 정한 기준을 넘지 못했기 때문이다.
- 자동 조건을 채운 실행이 적어(3번), 관문의 자동 판단을 믿을 만한지는 이번에도 모른다.
