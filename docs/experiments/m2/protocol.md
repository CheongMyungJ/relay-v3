# M2 평가 규약

- 상태: 초안. 첫 배치를 돌리기 전에 '고정'으로 바꾸고 커밋한다. 고정한 뒤에는 바꾸지 않는다. 바꿀 일이 생기면 사람에게 묻고 까닭을 `log.md`에 적는다.
- 결정: V14(실제 Claude 평가 n≥5, 배치마다 규모를 먼저 알림). 철학 8장, `docs/devices.md`의 끄는 조건.
- 도구: relay-v2 평가 도구(`relay-v2/app/eval`)에 v3 쪽(`relay3`)과 사람 역할 변형(`-handsoff`)을 더해 쓴다. 시나리오·숨긴 시험·판정·보고서는 v2 것을 그대로 쓴다.

## 1. 묻는 것

| # | 질문 | 견줄 쪽 | 무엇을 정하나 |
|---|---|---|---|
| Q1 | 늘 도는 독립 리뷰(V4)가 결과를 좋게 하나 | `relay3` 대 `relay3-noreview` | devices.md 독립 리뷰의 상태(관문 유지 / 표본 리뷰로 줄임) |

## 2. 쪽

| 쪽 | 무엇 |
|---|---|
| `relay3` | v3 앱 기본(질문: 결정마다 확인, 리뷰: 모두) |
| `relay3-noreview` | 같은 빌드, 평가용 환경 변수 `RELAY_ABLATE=review`로 리뷰를 끔(제품 설정이 아님) |
| `relay@auto` | v2 자율 유형(세션 주도, D557~D567). 기준 곡선 |
| `cli` | 맨 Claude Code CLI |
| `relay3-handsoff` | `relay3` + 사람 역할이 계약(의도) 승인 뒤 결과를 보지 않음 |
| `cli-handsoff` | `cli` + 사람 역할이 질문에는 답하지만 결과를 보지 않음 |

사람 역할 변형 `-handsoff`: 결과를 받아들이기 전에 확인하는 규칙과 "결과가 아는 사실과 어긋나면 지적할 수 있다"를 빼고, inspect_diff를 쓰지 않으며, 에이전트가 끝났다고 하면 받아들인다. 질문에는 평소처럼 답한다.

에이전트·사람 역할은 sonnet(effort medium), 판정은 sonnet. v2 평가와 같게 둔다(견줄 수 있게).

## 4. 지표

시나리오마다 쪽의 평균을 내고, 두 쪽의 차이는 시나리오마다의 평균 차를 시나리오 수로 평균한다. 구간은 시나리오 안에서 쪽마다 실행을 복원 추출한 bootstrap 95%(10,000번, 씨앗 고정). v2 `primary.mjs`의 방식이다.

| 지표 | 정의 | 좋은 쪽 |
|---|---|---|
| **P1 숨긴 시험** | 숨긴 시험을 모두 통과한 실행의 비율 | 높음 |
| P2 tests 점수 | 판정의 tests(1~5) | 높음 |
| P3 사람 차례 | 사람 역할의 차례 수 | 낮음 |
| P4 걸린 시간(사람 몫 뺌) | v2 eval의 '사람 응답 시간을 뺀 시간' | 낮음 |
| P5 입력 토큰 | 에이전트 입력 토큰(캐시 포함), relay3은 리뷰 호출 포함 | 낮음 |
| P6 결과 선호 | 가린 짝 판정 | 참고 |
| P7 burden, confidence | 짝 판정 | 참고 |
| G1 그림자 정밀도 | `relay3`에서 관문이 자동 조건을 채운(그림자 또는 자동 후보) 실행 가운데 숨긴 시험을 모두 통과한 비율 | 높음 |
| G2 그림자 재현율 | 숨긴 시험을 모두 통과한 실행 가운데 관문이 자동 조건을 채운 비율 | 참고 |

도구 문제(`harness_error`, `human_error`)는 빼고 따로 센다. 시간·차례 제한과 포기는 빼지 않는다(실패로 셈).

## 5. 판정 규칙 (결과 전에 고정)

동등 한계 δ: P1은 10%포인트, P3은 사람 차례 2. 차이의 95% 구간이 ±δ 안이면 '같음', δ 밖이면 '다름', 걸치면 '모름'.

- **Q1 (리뷰):** `relay3 − relay3-noreview`의 P1과 P2.
  - P1이 같음이고 P2 차이의 구간이 0을 넘지 않으면(리뷰 쪽이 tests에서도 낫다는 근거가 없으면) → 독립 리뷰를 '표본 리뷰'로 줄인다. 다만 자동 머지 경로에서는 그대로 늘 돈다(V4).
  - P1이 다름(리뷰 쪽이 높음) 또는 P2 구간이 0보다 크면 → 늘 돎을 유지한다.
  - 모름이면 → 유지하고 등록부에 '모름'으로 적는다. M3에서 n을 늘린다.
- **Q2 (방향):** `relay3`이 `relay@auto`보다 P1에서 '다름(낮음)'이면 → M3로 가지 않고 원인을 찾는다. 같음이나 높음이고, P3이 `relay@auto`보다 '다름(높음)'이 아니면 → M3로 간다. `cli`와의 차이는 보고만 한다(v2와 같은 설계라 같은 방향일 것으로 본다).
- **Q3 (사람 손):** `relay3 − relay3-handsoff`의 P1.
  - '다름'(보통 쪽이 높음) → 사람의 사후 교정 몫이 크다. 이 모델에서는 자율 단계 2(계약만 사람)를 열지 않는다.
  - '같음' → 단계 2를 열 근거 하나. 열지는 그림자 실적과 함께 사람이 정한다.
  - `cli − cli-handsoff`도 같이 보고해, relay3의 몫이 CLI보다 작은지 본다.
- **Q4 (관문):** G1이 95% 이상(그리고 자동 조건을 채운 실행이 10개 이상) → 자동 머지 단계 1의 조건을 그대로 둔다. 95% 아래 → 조건을 빡빡하게(어느 조건에서 틀렸는지 보고) 고친 뒤 다시 잰다. 10개 아래 → '모름'.

## 6. 하지 않는 것

- 결과를 본 뒤 시나리오나 지표를 바꾸지 않는다. 더 보고 싶은 것은 '참고'로만 적는다.
- 같은 시나리오에서 바로 고쳐 다시 재고 결론을 내지 않는다(v2 자율 시리즈의 약점). 고친 것은 다음 규약에서 잰다.
- 판정 모델에 시나리오의 목적(무엇이 relay의 강점인지)을 주지 않는다. v2 판정 도구가 목적을 주고 있으면 이 평가에서는 뺀다.
