# M2 평가 규약

- 상태: 초안. 첫 배치를 돌리기 전에 '고정'으로 바꾸고 커밋한다. 고정한 뒤에는 바꾸지 않는다. 바꿀 일이 생기면 사람에게 묻고 까닭을 `log.md`에 적는다.
- 결정: V14(실제 Claude 평가 n≥5, 배치마다 규모를 먼저 알림). 철학 8장, `docs/devices.md`의 끄는 조건.
- 도구: relay-v2 평가 도구(`relay-v2/app/eval`)에 v3 쪽(`relay3`, `relay3-noreview`)과 사람 역할 변형(`--human-mode hands-off`)을 더해 쓴다. 시나리오·숨긴 시험·판정은 v2 것을 쓰고, 아래 7절의 차이만 둔다. 집계는 `app/eval/m2-primary.mjs`.
- 시범 실행: 도구를 만들며 실제 Claude로 시나리오 10에서 relay3 4회, cli 1회, 시나리오 01에서 relay3 1~2회를 돌렸다. 결과는 판정에 넣지 않는다. 시나리오 10의 시범을 보고 사람 역할 설명서(`guides/relay3.md`)에 끝내기 안내를 고쳤다(`log.md`).

## 2. 쪽

| 쪽 | 무엇 |
|---|---|
| `relay3` | v3 앱 기본(질문: 결정마다 확인, 리뷰: 모두) |
| `relay3-noreview` | 같은 빌드, 평가용 환경 변수 `RELAY_ABLATE=review`로 리뷰를 끔(제품 설정이 아님) |
| `relay@auto` | v2 자율 유형(세션 주도, D557~D567). 기준 곡선 |
| `cli` | 맨 Claude Code CLI |
| `relay3-handsoff` | `relay3` + 사람 역할이 계약(의도) 승인 뒤 결과를 보지 않음 |
| `cli-handsoff` | `cli` + 사람 역할이 질문에는 답하지만 결과를 보지 않음 |

사람 역할 변형 `-handsoff`: 결과를 받아들이기 전에 확인하는 규칙과 "결과가 아는 사실과 어긋나면 지적할 수 있다"를 빼고, inspect_diff를 쓰지 않으며, 에이전트가 끝났다고 하면 받아들인다. 질문에는 평소처럼 답한다.

에이전트·사람 역할은 sonnet(effort medium), 판정은 sonnet. v2 평가와 같게 둔다(견줄 수 있게).

- 회차: 쪽·시나리오마다 5.
- 실행 수: Q1·Q2 = 4쪽(`relay3`, `relay3-noreview`, `relay@auto`, `cli`) × 9 × 5 = 180. Q3 = 2쪽(`relay3-handsoff`, `cli-handsoff`) × 5 × 5 = 50. 합 230. `relay3`·`cli`의 보통 실행은 Q1·Q2와 Q3이 함께 쓴다.
- 배치: 시나리오 묶음 셋(07·08·10 / 14·19·40 / 43·44·45). 배치마다 실행 수와 대략의 시간을 사람에게 먼저 알린다. 배치마다 보고서를 `docs/experiments/m2/reports/`에 커밋한다(컨테이너가 다시 시작돼도 남게).
- 명령(배치마다 시나리오만 바꿈): `node eval/run.mjs --scenarios <묶음> --runs 5 --arms relay3,relay3-noreview,relay@auto,cli --parallel 2 --quality-overlay --no-judge-purpose`. Q3은 `--arms relay3,cli --human-mode hands-off`로 따로 돈다. 짝 판정은 relay3:cli, relay3-noreview:cli, relay@auto:cli(도구의 기본)와 relay3:relay3-noreview, relay3:relay@auto(`--pairs`로 더함).

## 4. 지표

시나리오마다 쪽의 평균을 내고, 두 쪽의 차이는 시나리오마다의 평균 차를 시나리오 수로 평균한다. 구간은 시나리오 안에서 쪽마다 실행을 복원 추출한 bootstrap 95%(10,000번, 씨앗 고정). v2 `primary.mjs`의 방식이다.

| 지표 | 정의 | 좋은 쪽 |
|---|---|---|
| **P1 숨긴 시험** | 숨긴 시험을 모두 통과한 실행의 비율 | 높음 |
| P2 tests 점수 | 판정의 tests(1~5) | 높음 |
| P3 사람 차례 | 사람 역할의 차례 수 | 낮음 |
| P4 걸린 시간(사람 몫 뺌) | 걸린 시간 − 준비 시간(prepareMs) − 사람 역할 응답 시간 | 낮음 |
| P5 입력 토큰 | 에이전트 입력 토큰(캐시 포함). 두 앱 모두 앱이 부른 `claude -p`(v3 리뷰, v2 독립 리뷰·지식 검토) 포함 | 낮음 |
| P6 결과 선호 | 가린 짝 판정 | 참고 |
| P7 burden, confidence | 짝 판정 | 참고 |
| G1 그림자 정밀도 | `relay3`에서 내보내기 증거(리뷰 포함)의 관문이 자동 조건을 채운(그림자 또는 자동 후보) 실행 가운데 숨긴 시험을 모두 통과한 비율. 내보내기 결론이 없는 실행은 따로 센다 | 높음 |
| G2 그림자 재현율 | 숨긴 시험을 모두 통과한 실행 가운데 관문이 자동 조건을 채운 비율 | 참고 |

도구 문제(`harness_error`, `human_error`)는 빼고 따로 센다. 시간·차례 제한과 포기는 빼지 않는다(실패로 셈).

## 5. 판정 규칙 (결과 전에 고정)

동등 한계 δ: P1은 10%포인트, P3은 사람 차례 2. 차이의 95% 구간이 ±δ 안이면 '같음', δ 밖이면 '다름', 걸치면 '모름'.

- **Q1 (리뷰):** `relay3 − relay3-noreview`의 P1과 P2.
  - P1이 같음이고 P2 차이의 구간이 0을 넘지 않으면(리뷰 쪽이 tests에서도 낫다는 근거가 없으면) → 독립 리뷰를 '표본 리뷰'로 줄인다. 다만 자동 머지 경로에서는 그대로 늘 돈다(V4).
  - P1이 다름(리뷰 쪽이 높음) 또는 P2 구간이 0보다 크면 → 늘 돎을 유지한다.
  - 모름이면 → 유지하고 등록부에 '모름'으로 적는다. M3에서 n을 늘린다.
- **Q2 (방향):** `relay3`이 `relay@auto`보다 P1에서 '다름(낮음)'이면 → M3로 가지 않고 원인을 찾는다. 같음이나 높음이고, P3이 `relay@auto`보다 '다름(높음)'이 아니면 → M3로 간다. `cli`와의 차이는 보고만 한다(v2와 같은 설계라 같은 방향일 것으로 본다).
- **Q3 (사람 손):** `relay3 − relay3-handsoff`의 P1.
  - '다름'(보통 쪽이 높음) → 사람의 사후 교정 몫이 크다. 이 모델에서는 자율 단계 2(계약만 사람)를 열지 않는다.
  - '같음' → 단계 2를 열 근거 하나. 열지는 그림자 실적과 함께 사람이 정한다.
  - `cli − cli-handsoff`도 같이 보고해, relay3의 몫이 CLI보다 작은지 본다.
- **Q4 (관문):** G1이 95% 이상(그리고 자동 조건을 채운 실행이 10개 이상) → 자동 머지 단계 1의 조건을 그대로 둔다. 95% 아래 → 조건을 빡빡하게(어느 조건에서 틀렸는지 보고) 고친 뒤 다시 잰다. 10개 아래 → '모름'.

## 6. 하지 않는 것

- 결과를 본 뒤 시나리오나 지표를 바꾸지 않는다. 더 보고 싶은 것은 '참고'로만 적는다.
- 같은 시나리오에서 바로 고쳐 다시 재고 결론을 내지 않는다(v2 자율 시리즈의 약점). 고친 것은 다음 규약에서 잰다.
- 판정 모델에 시나리오의 목적(무엇이 relay의 강점인지)을 주지 않는다. v2 판정 도구가 목적을 주고 있으면 이 평가에서는 뺀다.

## 7. v2 평가와 다르게 둔 것 (모든 쪽에 같게)

- **품질 기준 덧씌우기(`--quality-overlay`):** 모든 쪽의 평가 레포 첫 커밋에 relay-v3 `relay init` 초안의 `.relay/quality.json`을 넣는다(V19의 기본 자동 조건 `small` 포함). v3는 레포의 품질 기준으로 증거를 재므로, 이것이 없으면 증거가 비고 관문이 늘 사람 머지라 Q4를 잴 수 없다. 사용자가 relay를 레포에 들인 상태를 흉내 낸 것이다. v2 relay·cli에는 쓰이지 않는 파일이다. 시나리오 정의와 숨긴 시험은 그대로다.
- **깨우기의 시계 가림:** 사람 역할을 깨우는 '화면이 멈춤' 판단에서 Claude Code의 경과 시간·스피너를 가린다. v3 세션이 MCP 도구 안에서 사람의 승인을 기다리는 동안 시계만 돌아 사람 역할이 늦게 깨던 측정 인공물을 없앤다. 그래서 차례 수의 정의가 예전 v2 보고서와 조금 다르다.
- **판정에 목적을 주지 않음(`--no-judge-purpose`).**
- **끝내기:** v3는 [끝내기]를 누르면 내보내기 증거와 리뷰를 보이고 [끝 확정]을 받는다(V18). 그래서 Q1의 리뷰는 사람이 지적을 보고 세션에게 고치게 할 때만 코드에 닿는다(리뷰는 세션에 직접 넣지 않음, V4). Q1이 재는 것은 '리뷰 + 사람'의 값이다.

## 8. 알려진 한계

- **가림이 약하다:** relay3의 diff에는 `.relay/examples/<계약 id>.json`과 시험 이름의 `[<계약 id>:C1.1]` 태그가 있어 판정 모델이 쪽을 알아챌 수 있다. P6·P7(짝 판정)은 참고로만 쓴다.
- **손 뗀 사람의 어김:** 기계로 세는 것은 diff 보기·변경 탭 열기다. 결과를 바로잡는 말은 세지 않으므로, Q3 해석 전에 hands-off 실행의 `turns.jsonl`을 훑는다.
- 사람 역할·판정 모두 Claude(sonnet)이고 쪽마다 처음 쓰는 사람이다.
