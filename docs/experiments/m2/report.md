## 3. 읽기

1. **결과의 질(P1)은 네 쪽이 비슷했고, relay3은 사람 차례와 토큰이 가장 많았다.** v3가 v2 자율보다 낫다는 근거도, 못하다는 근거도 이번 n으로는 없다. 차례가 많은 까닭은 원칙이 요구하지 않은 단계에서 나왔다([p3-decomposition.md](p3-decomposition.md): Work 나누기, 리뷰 왕복, 예시 파일 불일치, 리뷰 기다림, 두 단계 끝, 그리고 고친 버그 둘).
2. **의도 정리가 결과를 가른다(사용자의 처음 관찰 앞쪽).** 대충 쓴 요청(44)에서 의도를 묻지 않는 맨 CLI는 0/5, 묻는 세 쪽은 3/4~4/5였다.
3. **의도 정리 뒤 사람이 손을 떼면 결과가 나빠졌다(관찰 뒤쪽은 이번 모델에서 아직 아님).** relay3은 0.79 → 0.52, CLI도 0.76 → 0.56. 손을 떼면 '물어야 할 것을 묻지 않음'(43의 음수 반올림)과 '덜 된 진단'(14)이 그대로 결과로 간다. v3의 바닥(사람이 계약과 결과를 본다)이 실제로 일을 하고 있다.
4. **계약이 '끝'의 정의가 되면, 덜 된 계약을 아무도 못 잡는다(14).** 계약은 다 met, 리뷰는 올림 없음, 관문은 자동 조건을 채웠는데 숨긴 시험은 실패했다(G1 1/4). 자동 머지를 기본 꺼짐으로 두고 그림자부터 쌓는 설계(V3, 원칙 4)가 왜 필요한지 보여 준다.
5. **리뷰는 결과를 조금 낫게 했지만(P2) 비쌌다.** 리뷰 올림의 대부분이 structure/low여서 자동 조건을 늘 막았고, 사람이 지적을 손으로 옮기는 왕복이 차례를 늘렸다. medium 이상만 올림으로 세면 자동 조건 16회, G1 13/16(81%)으로 여전히 95% 아래다(탐색, 규약 밖). 리뷰만 느슨하게 해서는 자동 머지가 안전해지지 않는다.
