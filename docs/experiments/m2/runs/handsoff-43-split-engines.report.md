A는 요청과 무관한 .relay/examples JSON 파일을 추가했고 test/existing.test.js도 건드렸다. 그래서 범위가 B보다 넓다. cron과 markdown은 두 쪽 모두 숨긴 시험을 통과했다. cron 구현은 거의 같고, 일·요일 OR 규칙도 둘 다 맞게 처리했다.
  - 경험 전체 cli (relay-v3 6, 맨 CLI 7) — B는 수고가 크게 적었다. A는 명확성, 통제, 복구, 확신에서 앞섰지만 대기와 반복 확인이 길었다. 요청한 동시 진행은 양쪽 모두 못 지켰다. 전체로는 B가 약간 낫다고 본다.

### 사람 역할의 말

- [relay3#1 좋음] 계약 탭에 줄별 예시와 근거가 정리돼 있어서 승인하기 쉬웠다. 증거 탭이 못 미친 까닭을 구체적으로 알려 줘서 에이전트가 고칠 수 있었다.
- [relay3#1 불편] 모듈별로 나눠 동시에 진행해 달라는 요청을 에이전트가 따르지 않고 세션 하나로 순서대로 만들었는데, 그 점을 되묻거나 알려 주지 않았다. 증거를 재고 리뷰를 도는 동안 몇 분씩 기다려야 했다.
- [relay3#2 좋음] 계약 초안 단계에서 세션이 모호한 규칙(cron 일/요일, 거듭제곱, 오류 형태)을 하나씩 물어 정리해 준 점, 증거 탭에 못 미침의 까닭이 구체적으로 나온 점이 좋았다.
- [relay3#2 불편] 증거 재기와 독립 리뷰를 기다리는 시간이 길었고, 세션은 not_met의 이유를 몰라 내가 증거 탭의 문구를 터미널에 옮겨 줘야 했다. 또 요청에 있던 모듈별 병렬 진행은 세션이 하나로 처리해서, 별도로 나뉘어 진행되는지 알 수 없었다.
- [relay3#3 좋음] 계약을 먼저 내고 사람만 아는 규칙(cron 일·요일, round 등)을 선택지로 물어서 확인하는 흐름이 명확하고 수고가 적었다. 계약 탭에 예시와 근거가 정리되어 승인하기 쉬웠다.
- [relay3#3 불편] 모듈별로 나눠 동시에 진행해 달라는 요청을 에이전트가 따르지 않고 혼자 한 번에 만들었다. 계약 줄 4개가 못 미침으로 남았는데 원인을 못 찾은 채 끝났고, 리뷰 지적 5건도 반영 없이 끝나서 결과가 맞다는 확신이 약했다.
- [relay3#4 좋음] 계약 단계에서 에이전트가 필요한 것만 하나씩 물었고, 계약에 예시가 붙어 있어 요구와 맞는지 한눈에 볼 수 있었다.
- [relay3#4 불편] 증거 재기가 오래 걸렸고 그 사이 HEAD가 바뀌어 낡은 증거가 남았다. 끝낼 때는 리뷰 지적 9개(XSS 포함)가 있었는데, 고치라고 말하는 방법이 없어서 그대로 끝내야 했다.
- [relay3#5 좋음] 계약 단계에서 세션이 꼭 필요한 것만 선택지로 물었고, 계약에 예시가 구체적으로 적혀 있어 승인하기 쉬웠다. 증거 탭이 못 미침 줄과 까닭을 알려 줘서 문제를 짚어 고치게 할 수 있었다.
- [relay3#5 불편] 요청한 '모듈별로 나눠 동시에 진행'은 실제로 되지 않았고 세션이 한 줄로 순서대로 만들었다. 시험이 약 100초 걸렸고 증거 재기와 리뷰 대기도 길었다. 또 예시 파일을 손으로 잘못 써서 못 미침이 생겼다.
- [cli#1 좋음] 요청 한 번으로 세 모듈이 동시에 만들어지고 브랜치 하나로 합쳐져 전체 시험까지 통과했다.
- [cli#1 불편] 병렬 에이전트가 도는 동안 세부 진행이 잘 안 보였고 내용은 요약만 믿어야 했다. 임시 워크트리 브랜치가 남은 것도 아쉽다.
- [cli#2 좋음] 요청 한 번으로 세 모듈과 시험을 만들고 브랜치 하나에 커밋까지 끝냈고, 형식과 결정 사항을 요약으로 알려 줬다.
- [cli#2 불편] 구현을 서브에이전트로 나누지 않고 직접 했다. 시험만 병렬로 돌렸다. 또 시험 출력 파일을 / 아래에 남겼고, 지우려다 막혀서 나더러 지우라고 했다.
- [cli#3 좋음] 한 번 요청으로 세 모듈을 병렬로 나눠 만들고 브랜치 하나에 커밋까지 끝냈다. 에이전트가 먼저 묻지 않고도 정한 동작을 요약에 정리해 줬다.
- [cli#3 불편] 일/요일 규칙이나 거듭제곱 같은 세부 규칙을 에이전트가 묻지 않고 스스로 정했다. 결과는 직접 확인하지 않았다. 중간에 markdown 시험의 단언 한 줄을 지웠다고 해서 약간 찜찜했다.
- [cli#4 좋음] 요청 한 번으로 세 모듈을 알아서 병렬로 나눠 만들고 브랜치 하나로 합쳐 커밋까지 해 줬다. 마지막에 명세에 없던 결정도 정리해서 알려 줬다.
- [cli#4 불편] 하위 에이전트가 일하는 동안 화면에 진행 상황이 거의 안 보여서 오래 기다렸다. markdown 쪽 시험이 여러 번 실패해서 고치는 데 시간이 걸렸는데, 무슨 일인지 알기 어려웠다.
- [cli#5 좋음] 한 번 요청으로 세 모듈과 시험이 만들어져 브랜치 하나에 커밋됐다. 끝에 정리된 요약과 가정 목록도 도움이 됐다.
- [cli#5 불편] 모듈마다 따로 나눠 동시에 진행해 달라고 했는데 서브에이전트로 나누지 않고 시험만 병렬로 돌렸다. 루트에 임시 파일이 남았고, 기존 시험과 전체 npm test는 돌리지 않았다.
