### 사람 역할의 말

- [relay3#1 좋음] 계약을 먼저 보여 주고 승인하게 하며, 줄마다 예시가 붙고 증거 탭이 줄별로 충족 여부를 판정해 줘서 결과가 요구와 맞는지 확인하기 쉬웠다.
- [relay3#1 불편] 모듈별로 나눠 동시에 해 달라고 했는데 세션이 혼자 한 번에 처리했고, 일을 맡기는 단계에서는 이를 막을 방법이 없었다. 증거 측정과 리뷰를 기다리는 시간도 길었고 낡은 증거와 새 증거가 섞여 보여 헷갈렸다.
- [relay3#2 좋음] 계약 단계에서 질문에 답하고 줄마다 예시와 근거가 있는 계약을 승인한 점이 좋았다. 증거 탭이 어느 줄이 왜 못 미쳤는지 알려 줘서 고칠 곳을 짚을 수 있었다.
- [relay3#2 불편] 증거를 재고 리뷰를 기다리는 시간이 길었다. 에이전트가 예시 파일을 줄여 쓰고 시험 이름을 바꾸는 바람에 증거가 여러 번 어긋나 고치는 과정이 반복됐다. 요청한 '나눠서 동시에 진행'은 되지 않았고 에이전트가 한 번에 썼다.
- [relay3#3 좋음] 계약 단계에서 질문에 답하고 계약을 읽은 뒤, 예시가 잘못된 부분(C4.2)을 승인 전에 고치게 한 점이 좋았다. 증거 탭이 못 미침의 까닭(예시 자료 불일치, 시험 이름 변경으로 인한 래칫)을 짚어 줘서 원인을 찾을 수 있었다.
- [relay3#3 불편] 모듈을 나눠 동시에 진행해 달라고 했는데 세션 하나가 순서대로 다 구현했고, 이 요청은 계약에도 반영되지 않았다. 증거 측정과 독립 리뷰에 몇 분씩 걸렸다. 리뷰를 돌릴 때마다 새 지적이 나와 어디서 멈출지 내가 정해야 했고, 지적을 세션에 옮겨 말하는 것도 내 몫이었다.
- [relay3#5 좋음] 계약을 먼저 보고 승인하는 흐름과, 증거 탭이 '예시가 승인본과 다름', '기존 시험이 사라짐'처럼 실패 이유를 구체적으로 알려 준 점이 좋았다. 독립 리뷰가 링크 XSS 같은 실제 문제를 잡아 준 것도 도움이 됐다.
- [relay3#5 불편] '모듈마다 나눠 동시에' 하자는 요청은 반영되지 않았고 세션 하나가 순서대로 만들었는데, 그 사실을 먼저 알려 주지 않았다. 실패 원인을 세션이 처음엔 모른다고 해서 내가 증거 탭을 읽고 알려 줘야 했다. 시험이 오래 걸려 증거와 리뷰를 기다리는 시간이 길었고, 코드 수정이나 계약 변경마다 증거를 다시 재야 했다.
- [relay3-noreview#1 좋음] 세션이 계약을 먼저 내서 내가 아는 규칙(cron 이름·7·UTC)이 빠진 걸 구현 전에 바로잡을 수 있었다. 증거 탭이 C3 예시 불일치처럼 놓치기 쉬운 문제를 짚어 줬다.
- [relay3-noreview#1 불편] 병렬로 하라고 했는데 세션이 혼자 순차로 짰다. 시험이 100초 걸린다는 것도 내가 따로 짚어서야 고쳤다. 증거 측정이 오래 걸렸고, 낡은 증거 표시와 기다림이 헷갈렸다.
- [relay3-noreview#2 좋음] 계약을 먼저 보고 고쳐 달라고 할 수 있어서, 처음에 짧게 쓴 요청의 빠진 부분(병렬로 나눠서 합치기, 모호한 예시)을 구현 전에 바로잡을 수 있었다. 증거 탭에 못 미침의 까닭이 적혀 있어서 세션에 그대로 전달해 고칠 수 있었다.
- [relay3-noreview#2 불편] 증거를 재고 다시 재는 데 시간이 오래 걸렸고, 그동안 낡은 증거와 못 미침 표시가 먼저 떠서 헷갈렸다. 세션은 까닭을 모르겠다고 했는데, 증거 탭에는 까닭이 있었다. 그래서 내가 전해 줘야 했다.
- [relay3-noreview#3 좋음] 계약 단계에서 질문에 답하고 계약 탭에서 예시와 근거를 보고 고쳐 달라고 할 수 있었다. 내가 알던 것과 어긋난 부분(cron 이름, 코드블록 언어 class)을 구현 전에 바로잡았다.
- [relay3-noreview#3 불편] 모듈을 나눠 동시에 진행해 달라고 했는데 세션이 혼자 한 번에 만들었다. 이 부분은 계약에서도 제대로 다뤄지지 않았다. 증거 측정과 끝내기 확인이 오래 걸렸고, 예시 파일 형식이 달라 줄이 한 번 '못 미침'으로 나온 것도 헷갈렸다.

- [relay@auto#1 불편] 시험이 파일마다 50초씩 걸려서 기다리는 시간이 길었다. 자율 단계에는 승인 화면이 없어서 코드 블록 언어 표시가 빠진 것을 diff를 직접 훑어보고서야 알았다. 이미 합쳐진 결과를 보고 고치는 형태였다.
- [relay@auto#2 좋음] 의도 정리에서 범위와 오류 처리를 질문하고, 완료조건마다 확인 명령을 붙여 보여 줘서 요구가 맞게 들어갔는지 승인 전에 확인하기 쉬웠다.
- [relay@auto#2 불편] 모듈별로 나눠 동시에 하라는 요청을 에이전트가 자식 세션 없이 직접 구현했다. 나눈 방식도 미리 묻지 않았다. 또 질문 선택지가 내 요구와 달라 직접 입력을 여러 번 해야 했다.
- [relay@auto#3 좋음] 의도 정리에서 문법, 오류 처리, 시험 규칙을 하나씩 물어 줘서 내가 아는 내용을 정확히 전할 수 있었다. 마지막에는 자식 세션 3개 결과가 브랜치 하나로 합쳐지고 시험 25개가 통과했다.
- [relay@auto#3 불편] 자율 진행 단계에서 에이전트가 병렬로 나누라는 요청을 무시하고 직접 구현하기 시작해서 내가 끼어들어야 했다. 또 끝난 자식 세션이 세션 자리를 차지해 expr 자식이 한참 대기열에 머물렀고, 내가 직접 중단해서 자리를 내야 했다.
- [relay@auto#4 좋음] 모듈별로 자식 세션을 나눠 동시에 진행하고 결과를 브랜치 하나로 합쳐 주었다. 의도 정리에서 질문이 구체적이었고 요약·완료조건이 알기 쉬웠다.
- [relay@auto#4 불편] 의도 정리에서 이미 답한 내용과 겹치는 질문이 이어졌고, 부동소수 규칙처럼 코드로 알 수 없는 질문도 나왔다. round 음수 반올림 같은 세부 사항은 결과를 읽어 내가 직접 짚어야 고쳐졌다.
- [relay@auto#5 좋음] 의도 정리에서 범위와 규칙을 하나씩 물어 내 답이 완료조건으로 정리됐다. 자식 세션 셋으로 나눠 한 브랜치에 합쳐졌고, 합친 뒤 전체 시험이 통과했다.
- [relay@auto#5 불편] '나눠서 동시에 하라'는 요청이 의도 정리에 제약으로 적혔는데도 에이전트가 혼자 코드를 쓰기 시작해서, 내가 끼어들어 다시 시켜야 했다. 세션 상한 때문에 expr 자식이 대기열에 오래 막혀 끝난 자식을 직접 중단해 자리를 내야 했고, 그 일로 완료 때 경고가 한 번 더 떴다.
