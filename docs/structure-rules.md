- 근거:

## 1. 왜 넣나

래칫 셋(억누름, 중복, 바뀐 줄 커버리지)과 줄 수·시험 수 래칫은 어느 프로젝트에나 통하는 숫자다. 이 숫자들은 품질이 나빠지는 것을 막지만, 좋은 구조를 지키지는 않는다. 유지보수성을 가장 크게 가르는 것은 모듈을 어디서 나눴고 의존이 어느 방향으로 흐르는가이다. 그런데 그것은 프로젝트마다 다르다.

AI 세션은 Work마다 새 맥락으로 시작한다. 처음의 좋은 설계가 다음 Work로 이어질 통로는 셋인데, 그 가운데 효과가 확인된 것은 하나뿐이다.

| 통로 | 결과 |
|---|---|
| 지침("유지보수성 높게 설계하라") | 잴 수 없다. 모델은 이미 그렇게 하려고 한다 |
| 말로 적은 지식·규칙 | v2 지식(숨긴 시험 −0.10), M3 지식 잇기(같음 → 기본 끔) |
| 실행되는 검사 | v2 ESLint 경계 규칙만 끝까지 지켜졌다 |

그래서 설계 가운데 기계로 볼 수 있는 부분인 의존 방향을 검사로 굳힌다. 처음부터 설계를 잘하라고 시키는 대신, 사람이 정한 설계가 Work를 거듭해도 무너지지 않게 한다. 좋은 설계를 만드는 일은 여전히 사람·세션·리뷰어의 몫이다(9절).

## 2. 지금 있는 것과 그 한계

| 있는 것 | 하는 일 | 한계 |
|---|---|---|
| 초안의 경계 물음(V62, `engine/draft.ts` `boundaryRatchet`) | 폴더 이름이 정해진 목록(위층 `ui`·`api`·`cli`… / 아래층 `db`·`storage`…)에 맞으면 '앞:뒤' 경계를 묻는다. 답하면 `git grep … \| wc -l` command 래칫(`boundary-<앞>-<뒤>`)을 넣는다 | ① 이름 목록에 없는 구조(대부분의 레포, relay-v3 자신의 core·engine)는 후보가 없다. ② 줄을 글자로 찾는다: 다른 이름의 경로 별칭(`@data` → `src/db`)으로 가져오면 놓치고, 이름이 같은 바깥 패키지(`import db from 'db'`)나 다른 곳의 같은 이름 폴더는 엉뚱하게 센다. ③ 수만 견준다: 하나 고치고 하나 새로 어기면 같음으로 보인다. ④ 새로 어긴 줄을 증거에 보이지 못한다 |
| 규칙 승격(V42, M3d) | 세션이 지식의 `kind: rule` 항목을 lint 설정이나 스크립트로 옮기고 `rules`에 적게 한다(지침 문단). 허용 목록은 줄어들기만 한다 | 세션이 옮겨야만 돈다. M3에서는 한 번도 일어나지 않았다(0/14) |
| 레포가 이미 가진 도구(ESLint 경계, import-linter 등) | 빠른 검사로 돈다(초안은 import-linter가 있으면 `imports` 빠른 검사를 넣음) | 레포에 이미 있을 때만 돈다. 통과·실패뿐이라 이미 어긴 곳이 있는 레포에는 걸 수 없다 |

정리하면, 지금은 앱이 구조를 직접 읽지 않는다. 경계는 이름 짐작과 세션의 손에 맡겨져 있다. M3가 보였듯 세션의 손에 맡긴 것은 일어나지 않았다. 그래서 이 설계에서는 앱이 직접 import를 읽고, 사람은 고르기만 한다.

## 3. 무엇을 넣나

새 래칫 종류 `imports`. 사람이 정한 금지 방향을 어긴 import(파일 → 파일)의 집합을 앱이 기준 커밋과 결과 커밋에서 각각 세고, 결과 쪽에 새로 생긴 것이 있으면 나빠짐이다.

```json
{
  "id": "layers",
  "kind": "imports",
  "layers": [["src/cli/**"], ["src/engine/**"], ["src/adapters/**"], ["src/core/**"]],
  "forbid": [{ "from": ["src/renderer/**"], "to": ["src/engine/**", "src/adapters/**"] }],
  "exclude": ["**/*.generated.ts"]
}
```

- **`layers`**: 위에서 아래로 늘어놓은 묶음. 아래 묶음은 위 묶음을 가져오지 못한다. 위가 아래를 가져오는 것은 된다(건너뛰기 포함).
- **`forbid`**: 층으로 적기 어려운 낱낱의 금지.
- 둘 다 선택이지만 하나는 있어야 한다. 묶음은 glob이다. 묶음 안의 파일끼리, 그리고 어느 묶음에도 들지 않는 파일은 규칙 밖이다.
- **`include`·`exclude`**: 다른 래칫과 같다. 시험 파일(`test_globs`)은 기본으로 가져오는 쪽에서 뺀다. 시험은 여러 층을 함께 부르는 것이 자연스럽기 때문이다. `"tests": true`면 넣는다(열린 물음 10.2).

**왜 수가 아니라 집합인가.** 어긴 곳 하나를 고치고 다른 곳에서 새로 어기면 수는 같다. 하지만 설계는 무너졌다. 그래서 어긴 import 하나를 (가져오는 파일, 가져오는 대상 파일이나 모듈)로 이름 붙이고, 결과 집합에서 기준 집합을 뺀 것을 '새로 어김'으로 본다.

| 경우 | 판정 |
|---|---|
| 새로 어김이 있다 | 나빠짐 |
| 기준에만 있는 것(고친 곳)만 있다 | 좋아짐 |
| 둘 다 없다 | 같음 |
| 파일을 옮기거나 이름을 바꿨다 | git의 이름 바뀜 찾기로 기준 쪽 이름을 바꿔 견준다. 억누름 래칫이 옮긴 파일을 다루는 것과 같다 |

**왜 레포의 도구가 아니라 앱이 읽나.** 억누름·중복 래칫과 같은 까닭이다.

1. 아무것도 설치하지 않은 레포에서도 처음부터 돈다.
2. 언어마다 뜻이 같다.
3. 새로 어긴 import의 줄을 증거에 보일 수 있다.
4. 규칙이 `quality.json`에 있어 늘 지킴 파일이다. 지금 `.importlinter`, `.dependency-cruiser.*`, `.golangci.*`, ArchUnit 시험은 `DEFAULT_GUARD_PATHS`에 없다. 레포의 도구에 맡기면 이 파일들도 지킴 파일에 더해야 한다.

레포에 이미 있는 경계 도구는 그대로 빠른 검사로 둔다. 둘이 겹쳐도 해롭지 않다.

## 4. 앱이 import를 읽는 법

엔진의 순수 함수(`engine/imports.ts`, 언어가 늘면 `imports-<언어>.ts`)가 파일 내용에서 import를 뽑고 레포 안의 파일로 푼다. 레포 밖(패키지, 표준 라이브러리)은 버린다. 정밀한 파서는 쓰지 않고 줄 단위로 읽는다. 다만 주석과 문자열 안은 억누름 래칫의 주석 읽기를 다시 써서 거른다.

| 언어 | 뽑는 것 | 레포 안으로 푸는 법 |
|---|---|---|
| JS/TS | `import … from 'x'`, `export … from`, `import('x')`(글자 그대로일 때), `require('x')` | 상대 경로 + 확장자·`index` 찾기. `tsconfig*.json`의 `baseUrl`·`paths` 별칭. 작업 공간 패키지 이름(`package.json` `workspaces`) |
| Python | `import a.b`, `from a.b import c`, `from ..x import y` | 최상위 패키지(`src/` 배치 포함)를 찾아 모듈 경로 → 파일·`__init__.py`. 상대 import는 파일 자리에서 |
| Go | `import "mod/path/pkg"`(묶음 import 포함) | `go.mod`의 module 앞부분을 떼고 폴더로 |
| Java/Kotlin | `import com.x.y.Z`, `import com.x.y.*` | 소스의 `package` 선언으로 패키지 → 폴더 표를 만들어 푼다 |
| Rust | `use crate::a::b`, `use super::…`, `mod x;`, 작업 공간 crate 이름 | 모듈 트리(`mod` 선언과 파일 자리)와 `Cargo.toml` 작업 공간 멤버 |

**보지 못하는 것.** 이것들은 어김으로 세지 않고 '못 봄'으로 센다(8절의 지표).

- 계산된 경로의 동적 import
- 리플렉션과 DI 컨테이너
- Java의 같은 패키지 참조와 완전한 이름으로 쓴 참조(import 없이)
- C·C++ 같은 표에 없는 언어

규칙 묶음에 든 파일 가운데 '못 봄'이 많은 언어는 후보를 내지 않는다(5절).

**비용.** 기준·결과 커밋의 소스 파일을 읽는 것은 중복 래칫과 같은 길(adapters `readBlobs`)이다. 기준 커밋 결과는 SHA로 캐시한다.

## 5. 규칙은 어디서 오나 (초안 만들기)

이 장치에서 가장 중요한 부분이다. 규칙이 곧 설계이기 때문이다. 앱은 설계를 지어내지 않는다. 지금 코드에서 이미 지켜지고 있는 방향을 찾아 이름을 붙이고, 사람이 고른 것만 굳힌다.

1. **import 그래프를 만든다.** 지금 커밋의 모든 소스 파일에서 4절대로 뽑는다. 시험 파일은 뺀다.
2. **폴더 그래프로 줄인다.** 소스 뿌리(`src/`, 언어 단위의 폴더, Go·Python 패키지, Rust crate) 아래 깊이 하나·둘의 폴더를 마디로 삼는다. 마디 사이 가져오기 수를 화살표 무게로 삼는다.
3. **후보를 낸다.** 최대 다섯이고, 강한 것부터 낸다.

   | 후보 | 조건 | 묻는 글 예 |
   |---|---|---|
   | 층 | 폴더 그래프에서 무게가 가장 작은 화살표 몇 개(합이 전체의 2% 이하)를 빼면 순환이 없다 | 'src의 층: cli → engine → adapters → core (아래가 위를 가져온 곳 지금 0)' |
   | 한쪽 방향 | A → B가 5 이상이고 B → A가 0 | '`db`는 `api`를 가져오지 않는다 (반대쪽 50)' |
   | 거의 한쪽 | A → B가 10 이상이고 B → A가 1~2 | '`core`는 `ui`를 가져오지 않는다 (지금 어긴 곳 2: `core/fmt.ts:3` …)' |

   - 거의 한쪽 후보를 고르면 어긴 2곳은 기준에 남는다. 래칫이므로 먼저 고치라고 하지 않는다.
   - 층 후보는 위상 정렬로 순서를 정하고, 같은 단계의 폴더는 한 묶음으로 둔다.
4. **묻는다.** 초안 화면과 `relay init`의 묻는 것에서 지금의 '지킬 경계' 물음을 이 후보로 바꾼다.
   - 기본으로 고른 답은 없다(V62와 같음).
   - 후보마다 근거가 되는 수를 함께 보인다.
   - 사람은 고르거나, 고쳐 쓰거나, 손으로 더할 수 있다(CLI는 지금의 `--boundary 앞:뒤`를 그대로 받아 `forbid`로 넣는다).
5. **드라이런에서 지금 값을 보인다.** 예: '층 규칙: 지금 어긴 곳 0, 못 본 import 3(동적 import)'.

**이미 있는 도구 설정.** 첫판에서는 옮기지 않는다. ESLint `no-restricted-imports`, import-linter의 `layers` 계약 같은 설정을 읽어 같은 규칙을 후보 맨 위에 놓는 것은 둘째 판에서 한다. 그런 레포에는 이미 검사가 돌고 있어 서두를 까닭이 적다.

**relay-v3 자신이 첫 시험대다.** relay-v3에 초안을 돌리면 후보는 `eslint.config.mjs`가 이미 적은 층(core ← adapters ← engine ← cli, renderer와 shared의 금지)과 같아야 한다. 사람이 손으로 정한 설계를 앱이 그래프에서 다시 찾는지 보는 것이 후보 내기의 첫 맞춤 시험이다(7절).

## 6. 개발하는 동안

1. **Work마다.** 다른 래칫과 같다(quality-floor 4절).
   - [증거]에 '래칫 나빠짐: 층 규칙 새로 어김 1 — `src/core/gate.ts:4` → `src/engine/check.ts` (core는 engine을 가져오지 않음)'.
   - 쉬는 세션에 되먹임(V24)이 간다. 고치지 않고 머지하면 빚을 묻는다(V40).
   - 관문은 바꾸지 않는다. 나빠짐은 '래칫 나빠짐'으로 사람 머지다(열린 물음 10.1).
2. **규칙을 푸는 길.** 규칙은 `quality.json`에 있어 늘 지킴 파일이다.
   - 세션이 `layers`를 고치거나 `exclude`를 넓히면 늘 사람에게 간다.
   - '규칙이 틀렸다'는 세션의 말은 되먹임의 '까닭을 대고 넘김'으로 남는다. 사람이 규칙을 고치는 PR로 받는다.
3. **새 폴더가 생길 때(둘째 판).**
   - 이 경우 지금은 구조 변경 신호만 뜬다.
   - 앞으로는 [설정]의 '새로 쓸 수 있는 래칫'(quality-floor 6절)에 '새 폴더 `billing/`: 지금 가져오는 방향 `api → billing → db`. 층 규칙에 넣을까요?'를 보인다.
   - 고르는 것은 사람이다. 세션의 지침으로 맡기지 않는 까닭은 V42의 0/14다.
4. **규칙 승격(V42)과의 관계.**
   - V42는 그대로 둔다.
   - 지식의 `kind: rule` 항목 가운데 'A는 B를 가져오지 않는다' 꼴은 둘째 판에서 앱이 `forbid` 후보로 바꿔 [설정]에 보인다. 세션이 검사를 짜지 않아도 승격되는 길이다.
5. **꼼수를 막는 법.**
   - 직접 import만 보므로, 허용된 중간 파일을 거쳐 다시 내보내면 빠져나간다(`ui → api/index.ts → db`).
   - 금지된 대상을 허용된 묶음으로 옮겨서 빠져나갈 수도 있다.
   - 이런 것은 독립 리뷰어의 `structure` 지적(V4)이 본다. 리뷰어에게 새로 어김이 없더라도 다시 내보내기가 생긴 파일을 래칫 증거와 함께 넘긴다.
   - 거쳐 가는 의존까지 막는 `transitive`는 첫판에 넣지 않는다. 장기 평가에서 이런 빠져나감이 보이면 더한다.

## 8. 끄는 조건 (devices.md에 올릴 것, 안)

| 장치 | 가정 | 지표 | 끄는 조건(안) | 최소 n |
|---|---|---|---|---|
| 구조 규칙 래칫 | 사람이 고른 의존 방향을 앱이 Work마다 검사하면 경계가 Work를 거듭해도 무너지지 않고, 뒤 Work가 구조에 기대는 변경을 더 싸게 한다 | 나빠짐 Work 수, 그 가운데 세션이 고친 비율, 사람이 규칙을 풀거나 지운 비율('규칙이 틀림'), 거짓 양성(사람이 틀린 셈으로 표시), 못 본 import의 몫, 장기 평가 봉인 과제 | ① 장기 평가에서 켬·끔의 봉인 과제 통과율과 뒤 Work 비용이 δ 안이면 초안 기본에서 뺀다(레포가 적은 규칙은 그대로 돈다). ② 나빠짐 Work 가운데 절반 넘게 '규칙이 틀림'으로 끝나면 알림으로 내리고 후보 내기를 고친다. ③ 거짓 양성이 20%를 넘는 언어는 그 언어의 읽개를 '제안만'으로 내린다 | 나빠짐 Work 30, 장기 평가 쪽마다 Work 30 |

장기 평가는 구조가 실제로 무너지는 판이어야 잴 수 있다. quality-floor 7절의 '30 Work 이상, 구조에 기대는 봉인 과제'와 같은 판을 쓰고, 미끼로 '층을 건너뛰면 쉽게 끝나는 요청'을 더한다. M3 판(3천 줄, 15 Work)으로는 부족했다.

## 9. 이 장치가 하지 않는 것

- **좋은 경계를 정하지 않는다.** 이미 있는 방향에 이름을 붙일 뿐이다. 레포의 구조가 처음부터 엉켜 있으면 후보가 없거나 약하다. 그때 경계를 세우는 일은 사람이 정하는 정리 Work의 몫이다.
- **모듈 안의 품질을 보지 않는다.** 이름, 추상화의 알맞음, 한 파일의 책임은 보지 않는다. 독립 리뷰어와 설계 메모(아래)의 몫이다.
- **설계 메모와 결정 기록은 이 문서 밖이다.** 큰 Work 앞에 바꿀 모듈·방향·버린 안을 적는 짧은 설계 메모, 구조 결정 기록(ADR)은 따로 설계한다. 그때 결정 가운데 검사로 바꿀 수 있는 것은 이 래칫의 `forbid`·`layers` 후보로 이어지게 한다.

## 10. 열린 물음 (사용자와 정함, 1~3은 2026-11-08 ✅ 안대로)

1. **관문에서의 무게.** 새로 어김을 다른 래칫처럼 '사람 머지'(막지 않음, 자동 머지 후보에서 빠짐)로 둘지, 더 무겁게 둘지(예: 고치지 않으면 내보내기를 막음). 안: 다른 래칫과 같게. 끄는 조건 ②를 잴 수 있으려면 막지 않아야 하고, 무게를 늘리는 것은 실적이 쌓인 뒤 정한다.
2. **시험 파일.** 기본으로 뺄지. 안: 뺀다. 시험이 여러 층을 부르는 것은 설계 위반이 아니다.
3. **초판의 언어 범위.** 안: JS/TS·Python·Go를 먼저 하고, Java/Kotlin·Rust는 시범에서 푼 비율을 본 뒤 한다. 품질 바닥 시범에서 JVM 쪽은 이 기계의 환경 탓으로 판정이 없었다.
4. **장기 평가.** 판 만들기와 실행 비용이 크다. 1단계(래칫, 후보, 시범)를 만든 뒤 규모와 비용을 따로 묻는다.

## 11. 순서

1. **1단계:** `imports` 래칫과 JS/TS·Python·Go 읽개, 초안 후보, 드라이런 값, 시험, relay-v3 자신으로 맞춤 시험, 30개 레포 시범(정적·드라이런).
2. **2단계:** Java/Kotlin·Rust 읽개, 이미 있는 경계 설정 옮기기, [설정]의 새 폴더 안내, 지식 규칙 → `forbid` 후보.
3. **3단계:** 장기 평가(켬·끔), 끄는 조건 판정.

## 12. 만든 것 (1단계, 2026-11-08)

- **래칫(V74).** `imports` 종류, engine `imports.ts`(읽기), `import-rules.ts`(맞추기·비교), `ratchets.ts`의 `importsAt`. 관문·되먹임·빚은 다른 래칫 그대로이고, 관문 판 5(V76, 재생 digest 같음, epoch 1을 이음).
- **후보(V75).** engine `import-graph.ts`. 초안의 '지킬 경계' 물음은 이제 이 후보만 낸다. 드라이런은 imports 래칫의 지금 값을 낸다.
- **맞춤 시험.** relay-v3 자신에서 첫 후보는 `src`의 층 cli·main > engine·preload·renderer > adapters·shared > core(어긴 곳 0, 못 본 import 0)이다. eslint.config.mjs가 막는 방향(core·adapters·engine이 위를 가져오기)을 모두 막는다([어댑터] structure.test.ts).
- **시험.**
  - [단위] `imports.test.ts`, `import-rules.test.ts`, `quality.test.ts`(새 칸), `draft-recipes.test.ts`(후보 묻기, `structureRatchet`).
  - [어댑터] `structure.test.ts`.
  - [흐름] `works-structure.test.ts`(금지된 import → [증거] 나빠짐 → 되먹임 → 빚), `works-draft.test.ts`·`cli.test.ts`(후보와 답).
  - [스모크] `draft.spec.ts`(초안 화면의 구조 후보, `smoke-draft-02-answers.png`를 열어 봄).
- 시범은 [experiments/structure-rules-pilot/report.md](experiments/structure-rules-pilot/report.md).

**설계와 다른 것.**

- **`forbid`의 `from`은 glob 목록이다.** 3절의 첫 예는 글 하나였다. `to`와 같은 꼴로 맞췄다.
- **이름 공간 패키지와 Go 패키지는 폴더를 대상으로 한다.** 4절은 '파일이나 모듈로 푼다'였다. 이름 공간 패키지는 `__init__.py`가 없는 Python 패키지다. 규칙의 묶음은 폴더 아래를 함께 맞춘다.
- **Python의 import 대상은 정확히 모듈이어야 한다.** `import a.b`, `from a.b import …`에서 `a.b`가 레포에 없으면 앞부분(`a`)으로 물러서지 않고 '못 봄'으로 센다. 그런 것은 C 확장이나 만든 파일이다(markupsafe `._speedups`, humanize `._version`).
- **옛 경계 물음과 `git grep` 래칫은 없앴다.** 옛 경계 물음은 폴더 이름 목록으로 짐작했다. 옛 quality.json의 `boundary-*` command 래칫은 그대로 돈다. 손으로 적는 `--boundary 앞:뒤`는 같은 뜻의 `forbid`가 된다.
- **읽지 않는 언어 파일은 조용히 빠진다.** Java/Kotlin·Rust 레포에 손으로 규칙을 적으면 늘 같음이다. 이 사실은 드라이런의 '읽은 소스 N'이 드러낸다. 2단계에서 읽개를 더한다.
- **src/core에는 타입과 읽기 검증만 넣었다.** 지금 4,992줄이다. quality.ts가 파일 상한을 넘어, 기본 목록 둘을 `core/quality-defaults.ts`로 옮겼다.
- **electron-vite의 ESM 심 문제를 피했다.** 이 심은 소스 안의 `import … from '…'` 꼴 글을 마지막 import로 읽고, 그 뒤에 심을 끼운다. 그래서 imports.ts의 주석에 그 꼴을 그대로 적지 않는다.
