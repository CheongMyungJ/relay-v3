**V32 제출 때 기준 확인을 뺀다.** `engine/probe.ts`, `main/works-probe.ts`, core `probeVerdicts`, 렌더러의 기준 배지와 요약 줄, `WorkRecord.probe`·`WorkView.probe`, 지침의 제출 때 확인 사실을 지운다. 지침의 '지킴 시험은 기준에 있는 API만 쓴다'는 사실로 남긴다(V33이 쓴다). 등록부의 V28 줄은 상태를 '뺌'으로 두고 M2.1의 값을 남긴다. core에서 줄이 줄어 상한에 여유가 생긴다.

**V34 예시와 시험 불일치의 뜻.**

- V27(앱이 예시 자료를 씀)은 그대로다. 커밋된 예시 파일이 승인본과 다르면 여전히 사람 머지 사실이다.

**만든 것(2026-11-06).** 위대로 고쳤다. 설계가 정하지 않은 곳과 작게 바꾼 곳은 아래다.
- 리뷰 프롬프트의 1번(영어): 'a tagged test checks another input, another output or error, or a weaker assertion than its approved example, or an approved example has no test that really checks it. The approved examples are in the contract below, and relay writes them to the examples file (see "examples file" in the evidence summary). A tagged test that checks exactly the approved input and output (or error) is not a mismatch, even if it writes these values in the test instead of reading them from the file.' V27 판의 '시험은 예시를 그 파일에서 읽어야 한다'(the tests are meant to read …)도 함께 뺐다: 남기면 리뷰어가 읽지 않은 시험을 다시 불일치로 볼 수 있다. 승인된 예시가 계약에 있다는 말을 더했다(무엇과 견주는지).
- `REVIEW_PROMPT_VERSION`은 4다. 판 3으로 끝난 미리 리뷰는 내보내기에 다시 쓰지 않으므로, 고친 빌드로 이어 쓰는 Work는 [끝내기]나 PR에서 리뷰를 한 번 더 부른다. `scripts/review-replay.ts`는 판이 다른 줄이 있는 결과 파일을 잇지 않는다(그대로).
- 지침 §1의 예시 칸(영어): 'Write `input` and `output` as JSON values that a test can use as they are (`[3, 1, 2]`, `{"name": "a", "count": 2}`, `0.5`), not as words that describe a value; what can only be said in words goes in `note`.' JSON에 없는 값의 규칙(V27) 바로 앞에 둔다. 보기 값은 평가 시나리오의 말을 쓰지 않았다. `error`는 설계대로 넣지 않았다(오류는 메시지 글이 값일 수 있다). 지침 §4의 '시험은 예시를 그 파일에서 읽는다'는 그대로 둔다(V27): 리뷰가 박아 쓴 값을 불일치로 보지 않을 뿐, 파일에서 읽는 길이 여전히 기본이다.
- 계약 검사(`validateContract`)는 바꾸지 않았다: 예시 값이 글인지 앱이 가르지 않는다(값이 글자열인 예시도 맞을 수 있다).
- 시험: [단위] `review.test.ts`(새 1번의 글, 박아 써도 그대로 확인하면 아님, 옛 'hard-codes'·'meant to read'가 없음, 판 4), `instructions.test.ts`(두 질문 방식에서 JSON 값 문장이 예시 칸 안, JSON에 없는 값 규칙 앞). **V35 넘기고 다시 걸기.** 상자의 [세션에 넘기기]는 지적과 사실을 세션에 보내고(V24 꼴), 끝을 '고친 뒤 끝냄'으로 다시 건다. 세션이 쉬고 새 head의 증거와 리뷰에 열린 것이 없으면 Work가 끝난다(V25의 걸린 끝과 같은 길). 열린 것이 있으면 상자가 다시 뜬다. 사람은 [취소]로 언제든 푼다. [증거] 탭의 [세션에 넘기기]는 끝을 걸지 않는다(지금과 같다).
